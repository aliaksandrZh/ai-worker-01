# 07: Orchestrator core — state machines, admission, queue

**What to build:** The orchestration core: Workflow / Task / Run / AgentSession / OrchestrationJob records with the spec's state machines; `ContainerInstance` records tracking the desired/observed machine of `03 §5` (`02 §15`); Task creation linking input artifacts through `TaskArtifactInput` (`02 §10a`); the one-unfinished-Task-per-Workflow invariant enforced both by admission logic and by the partial unique index + transactional Task+Job creation with a `SELECT … FOR UPDATE` lock on the Workflow row; admission rules (same-Workflow command rejected while a Task is unfinished — not queued; cross-Workflow commands queued); transactional claim/lease with expiry returning jobs to `pending`; global FIFO by `available_at` then `priority`; `max_concurrent_runs` counting Claimed/Starting/Running/Stopping Runs (slot freed only at terminal state + confirmed stop); command → Task creation through routing rules with the selected `AgentProfileVersion` pinned (missing/disabled/unready profile → `agent_profile_not_configured`, rejected before any Task exists); Workflow-scoped Run serialization hook (a Workflow's next Run — any Task type — starts only after the previous Run's terminal callback is persisted).

## What has been done (2026-11-20, agent)

- **Entities + migration `AddOrchestratorCore`**: Workflow, OrchestrationTask (`table task`), Run, AgentSession, OrchestrationJob, ContainerInstance, TaskArtifactInput, Artifact (FK target only — no writer this ticket) per `02` §9–§19 with the §23 indexes, including the live-tested `ux_task_one_unfinished_per_workflow` partial unique index and the partial `trigger_command_id` uniqueness.
- **Admission stage** (`Orchestrator/Orchestration/CommandAdmission.cs`, invoked by the task-06 processor right after authorization, same transaction): closed-WorkItem / `workflow_failed` / `unfinished_task_exists` rejections, routing resolution (repo rule overrides global; priority descending), profile/version gates (`agent_profile_not_configured` vs `agent_image_not_ready` split per decision 35), the `/code` latest-successful-plan gate (decision 80), then Workflow-row `FOR UPDATE` + Task (+`TaskArtifactInput` for /code) + OrchestrationJob + command→`queued` in one transaction. The authorization gate's rejection reasons are preserved — admission never re-admits a rejected command. `/status`, `/help`, `/stop`, `/retry` stay untouched at admission (tickets 08/14/15).
- **Job queue** (`Orchestrator/Orchestration/JobQueueWorker.cs`, an `IWorkerCycle` after the command processor): lease sweep (Task `claimed→queued`, deletes only never-dispatched `pending` Run rows; job back to `pending` with `last_error = "claim lease expired"`), FIFO claim (`available_at`, then priority desc) via `FOR UPDATE SKIP LOCKED` inside one transaction, paused repositories filtered out in the claim query (decision 75), a per-tick skip set so swept/released jobs are never re-claimed in the same tick, and cap-aware batch sizing (`claimed Tasks + Runs in starting/running/stopping < max_concurrent_runs`, decision 75). Claim-time rechecks (04 §2/06 §12) cancel-with-recorded-reason (Task `cancelled`, Job `cancelled`, command `failed` + reason, Outbox notice) or release-claim (transient permission, serialization hook, stale pause race). A valid claim prepares Run (`pending`, next attempt) + AgentSession (`provisioning`, 1:1) + ContainerInstance (`desired=running`, `observed=unknown`) and hands off to `NullRunDispatcher` (ticket 09 replaces).
- **Configuration & metrics**: `ConfigurationState` now carries `MaxConcurrentRuns` from the config plane; the health metric placeholders became real gauges (`queuePendingJobs`, `queueOldestJobAgeSeconds`, `queueClaimWaitSeconds`, `activeRuns`) plus `jobsClaimedTotal`, `leaseExpirationsTotal`, `claimCancellationsTotal`.
- Tests: 14 model/index tests (`OrchestratorCoreModelTests`), ~20 admission tests (`AdmissionTests`), ~20 queue/recheck tests (`JobQueueWorkerTests`, `OrchestrationConstraintTests` — live-Postgres unique/partial-index/serialization constraints), vocabulary tests.
